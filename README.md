# Technical Test: Todo App

A small todo list manager with a **FastAPI** backend and a **Vite + React + TypeScript** frontend.

Users can create tasks with an optional description, mark them as completed, mark them as favorite and delete them. Favorite tasks are shown in their own section. All changes are persisted by the backend in a JSON file.

## Project structure

```
.
├── backend/
│   ├── requirements.txt
│   └── app/
│       ├── main.py            # FastAPI app, CORS and router registration
│       ├── dependencies.py    # TodoDB instance exposed through get_db()

│       ├── routers/
│       │   └── todos.py       # /todos endpoints
│       └── models/
│           ├── todo.py        # Todo model
│           └── payloads.py    # Request bodies (create / update)
└── frontend/
    └── src/
        ├── App.tsx            # State, data loading and actions
        ├── api/todo.ts        # HTTP client for the backend
        ├── types/todo.d.ts    # Todo type
        └── components/
            ├── TodoForm.tsx   # Title + description form
            ├── TodoList.tsx   # Titled section with a list of tasks
            └── TodoItem.tsx   # A task: checkbox, favorite and delete buttons
```

## Requirements

- Python 3.10+
- Node.js 18+

## Getting started

1. Create a virtual environment and install the backend dependencies:

   ```bash
   cd backend
   python -m venv .venv
   source .venv/bin/activate  # On Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Install the frontend dependencies:

   ```bash
   cd ../frontend
   npm install
   ```

3. With the virtual environment still active, start both servers:

   ```bash
   npm run dev
   ```

   This starts the backend at `http://localhost:8000` (with auto-reload) and the frontend at `http://localhost:5173`. They can also be started separately with `npm run dev:backend` and `npm run dev:frontend`.

4. Open `http://localhost:5173`. Tasks are loaded automatically.

The interactive API documentation is available at `http://localhost:8000/docs`.

## API

| Method   | Endpoint      | Body                                     | Response                          |
| -------- | ------------- | ---------------------------------------- | --------------------------------- |
| `GET`    | `/todos`      | —                                        | `200` list of todos               |
| `POST`   | `/todos`      | `{ "title": string, "description"?: string }` | `201` created todo; `422` if the title is empty |
| `PATCH`  | `/todos/{id}` | `{ "completed"?: bool, "favorite"?: bool }` | `200` updated todo; `404` if not found |
| `DELETE` | `/todos/{id}` | —                                        | `204`; `404` if not found         |

A todo looks like this:

```json
{
  "id": "4a183f67-3bd1-48b1-b16b-5492e9a9b242",
  "title": "Learn Vite",
  "description": "",
  "favorite": false,
  "completed": false
}
```

## Implementation notes

- **Backend as the source of truth.** After every action (create, complete, favorite, delete) the frontend fetches the list again instead of patching its local state, so the UI always shows what is stored.
- **Routing.** Endpoints live in an `APIRouter` (`routers/todos.py`) and receive the storage through FastAPI's `Depends(get_db)`. `main.py` only builds the app, which makes it easy to add new routers or swap the storage (for example in tests).
- **Partial updates.** A single `PATCH /todos/{id}` endpoint updates `completed` and/or `favorite`; only the fields sent are changed.
- **Input validation.** `POST /todos` accepts only `title` and `description`, so clients cannot choose the `id` or the initial state. The `id` is a UUID generated by the server.
- **Storage.** Data is kept in memory and written to `backend/app/todos.json` after each change. This is enough for the exercise but not safe for concurrent writes from several processes; a real deployment would use a database.
